## Archived development and mathematical context

The intended specialist audience is formalized foundations of Euclidean
geometry and the relation between planar symmetries, primitive length and
quadratic invariants. The contribution presented for assessment is an explicit
conditional dependency chain: it separates the length function from the
quadratic coordinate expression and exposes the exact hypotheses used by this
derivation. This is not a claim of a new identity, historical priority, or a
minimal axiom system. Palomar's research-interest assessment remains separate
from mechanical correctness.

A Lean 4 + Mathlib formalization accompanying an **AI-generated mathematical manuscript** titled
*The Coordinate Pythagorean Theorem from Planar Isotropy: An Axiomatic Derivation with Lie-Theoretic Extensions* (original draft: 18 August 2026; revised and extended edition: 12 October 2026).

**Manuscript authorship and origin:** the original text and proposed proof were generated by **OpenAI ChatGPT (GPT-6, High thinking effort)** in response to a research prompt from **Alessandro Odasso**, who asked whether ChatGPT could find an **original proof of the Pythagorean theorem**. The word "original" describes the question posed, not an independently established assertion of mathematical novelty. The group-theoretic main proof is formalized in Lean; the Lie-theoretic discussion explains additional structure without being required by the main theorem.

The project formalizes an axiomatic implication from **primitive congruence and planar symmetries** to the coordinate Pythagorean identity. The geometric length function is an independent function `L : ℝ → ℝ → ℝ`; it is **not** defined using `sqrt (x² + y²)`.

## Explicit foundational assumptions and automated axiom audit

**[Read AXIOMS.md for the precise eight geometric hypotheses and the kernel axiom audit.](./AXIOMS.md)**

The final theorem **does not** assume the Pythagorean identity, a Euclidean norm, or a Euclidean inner product as the definition of geometric length. It does explicitly assume:

1. A **linear** quarter-turn `Q` satisfying `Q(1,0) = (0,1)` and `Q²(P) = -P`.
2. A one-parameter **additive linear action** `F` containing `Q`, with `F(s+t) = F(s) ∘ F(t)`.
3. **Axial calibration** `L(z,0) = |z|` and **mirror symmetry** `L(x,-y) = L(x,y)`.
4. **Rigidity** `L(F(t)P) = L(P)` for each group element.
5. For the chosen vector `(a,b)`, an **axis-hit** assumption: some `F(t)` sends it to `(z,0)` with `z ≥ 0`.
6. `c = L(a,b)`.

For the separate infinitesimal-generator theorem, the requisite derivatives at zero and normalization `F(0)` are also explicit premises.

**Scope:** Lean checks that the conclusions follow from these assumptions. The project does *not* yet prove from more primitive incidence/congruence axioms that this entire rotation group exists, nor does it establish minimality or independence of the hypotheses. In particular, axis transitivity is an assumption, not a proven consequence of the presence of a single quarter-turn.

## Reproduce the Lean check

The exact Lean toolchain and a pinned Mathlib revision are provided.

```bash
lake exe cache get Mathlib.Analysis.Calculus.Deriv.Pow Mathlib.Analysis.Calculus.MeanValue Mathlib.Tactic.Convert Mathlib.Tactic.Linarith Mathlib.Tactic.Ring
lake build
bash scripts/verify-comparator.sh
```

The GitHub Actions workflow [`lean.yml`](./.github/workflows/lean.yml) runs the same check on pushes and pull requests and executes `#print axioms` for the main theorem and three supporting lemmas. It publishes the actual kernel-level dependencies in the build log, job summary, and an artifact named `lean-kernel-axiom-audit`. In the successful public audit, all four selected theorems depend only on `propext`, `Classical.choice`, and `Quot.sound`. The action now rejects any other reported kernel axiom dependency, including admitted proofs (`sorryAx`/`sorryAdmit`).

**Important distinction:** `#print axioms` lists **Lean's global kernel axioms**, not geometric premises such as `hRigid` and `hToAxis`; those are **explicit theorem parameters** listed in [AXIOMS.md](./AXIOMS.md). A successful kernel audit is not a proof that the geometric assumptions are minimal, historically novel, or derivable from weaker axioms.
